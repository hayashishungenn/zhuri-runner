# 微信小游戏平台合规调研（Phase 0）

> 调研日期：2026-11-25。来源均标注官方链接；政策随监管动态调整，**提审前必须以 mp 后台提交时的实际要求为准**。
> 标注 ⏳ 的事项 = 无法从公开官方文档完全确认，需在 mp 后台实际操作时验证，不得沿用本文件未证实结论。

## 1. 主体与注册

- **个人主体可注册小游戏**，但类目受限：个人主体**暂不支持**文化互动、角色类（角色扮演）、牌类（棋牌）三类目。
  来源：微信开放文档「类目设置」（developers.weixin.qq.com/minigame/...）、「微信小程序平台运营规范」（developers.weixin.qq.com/minigame/product）。
- 个人主体能力边界：**无微信支付接口**（不能内购/虚拟支付）、成员上限 15 项目 + 15 体验（企业 30+30）。
- **本项目定位与个人主体匹配**：休闲竞技（夸父逐日）+ 纯 IAA 变现，不涉内购，不涉棋牌/角色扮演类目。✅ 可行。
- ⏳ 待后台验证：注册时实际可选类目列表以提交页为准；"休闲游戏"类目的确切名称与层级。

## 2. 变现（IAA / 流量主）

官方指南：developers.weixin.qq.com/minigame/introduction/commercialization/ad

开通条件（满足任一）：
1. **累计独立访客 UV > 500** + 无刷粉、无严重违规（资格次日刷新生效）
2. 内置游戏圈产生有效活跃 + 发布官方帖 5 篇
3. 同公司主体名下已有已开通且持续变现 1 个季度的小程序（限公司主体）

可用广告组件（小游戏 4 种）：**激励视频**、banner、插屏、原生模板。
- 本项目核心点位：激励视频（复活）。P4 扩展：插屏（死亡结算后）+ banner（谨慎，影响体验）。
- ⏳ 待后台验证：**个人主体能否开通流量主**——官方指南条件一/二未限定主体类型（条件三明确限公司），社区实践为"个人主体 UV 达标可开通"，但需后台实际确认。

## 3. ICP 备案（硬性）

- 工信部要求：**2024 年起新注册小程序/小游戏须完成 ICP 备案方可上架**。
- 流程：mp.weixin.qq.com 后台 → 设置 → 备案入口；材料：负责人证件、（特殊行业）前置审批、按省份补充材料。
- 官方指引：developers.weixin.qq.com/minigame/product/record/record_guidelines.html；FAQ：.../record_faq.html。
- 备案查询：ICP 信息备案管理系统（beian.miit.gov.cn）。
- ⏳ 待后台验证：个人主体备案的省份差异材料（居住证/授权书等）。

## 4. 游戏类目资质（软著等）

- 个人主体上线**无内购**小游戏：无需版号（ISBN）；提审材料通常需 **《计算机软件著作权登记证书》+《游戏自审自查报告》+《开发者承诺函》**；部分场景以《著作权自我声明》替代软著（无特殊内容时），**以提交时后台实际要求为准**。
- 企业主体内购（IAP）：必须版号 + 文化部备案 + 软著——本项目不做内购，不适用。
- **行动项**：尽早启动软著登记（个人申请，周期 1~3 个月，可加急）；游戏完成度接近 P3 时办理。
- ⏳ 待后台验证：当前时点个人主体"益智休闲"类目是否强制软著（存在"自审自查报告+承诺函"可替代的说法，两说并存，以后台为准）。

## 5. 实名认证 / 防沉迷 / 适龄提示

- 所有微信小游戏**已全面接入腾讯健康系统**，且已与**中宣部实名认证防沉迷系统**对接——开发者**无需自行实现实名/防沉迷逻辑**，但需在 mp 后台「设置 → 游戏设置 → 中宣部实名认证系统接入」确认/同步游戏信息。
  来源：developers.weixin.qq.com/minigame/introduction/guide/zxbsm.html
- 防沉迷规则（2021"830 新规"）：未成年人仅周五六日及法定节假日 20:00–21:00 可玩 1 小时（平台侧执行，微信小游戏天然继承）。来源：jkyx.qq.com（腾讯健康系统）。
- **适龄提示**：后台设置适龄等级（本项目建议 8+）→ 平台审核 → 启动页统一展示。来源：developers.weixin.qq.com/minigame/introduction/guide/slts.html
- ⏳ 待后台验证：个人主体小游戏是否需在 nppa 防沉迷系统单独注册企业账号（文档面向企业；小游戏走腾讯健康系统渠道关联，个人主体实际操作路径待确认）。

## 6. 广告内容与展示规范

- 官方规范：**《小程序流量主运营规范》ad.weixin.qq.com/docs/74**（小游戏类目适用）。
- 关键红线：不得明示/暗示**诱导用户反复访问、点击广告**；激励发放必须以**真实看完**为条件（wx.createRewardedVideoAd 的 onClose(res.isEnded) 判断——本项目 AdService 已按此实现）；广告不得遮挡关键操作、不得在无资质品类展示。
- 广告层级：激励视频组件层级最高，覆盖普通组件——结算面板须避开激励视频展示期（本项目模拟层已按展示期吞输入，真机行为一致）。
- ⏳ 待后台验证：具体违规条款清单以 ad.weixin.qq.com/docs/74 最新版本为准（提审前重读）。

## 7. 包体限制

官方分包文档：developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubpackage.html

| 项 | 限制 |
|----|------|
| 主包 | **≤ 4MB** |
| 总包（主包+全部分包） | **≤ 30MB**（历史为 20M，已放宽；普通与虚拟支付场景一致） |
| 单个普通分包 | 不单独限制（受总包约束） |

- 本项目现状：纯代码生成几何体，主包远小于 4MB（构建产物实测约数百 KB 级）。P2 引入美术/音频后启动分包规划（P3 实测包体）。

## 8. 审核与运营红线（提审 checklist 关联）

- 神话题材改编：确保无宗教敏感表述（GAME_DESIGN 已约束为上古神话角色演绎）。
- 不含《神庙逃亡》等商业游戏资产（ASSET_LICENSES 已约束，REFERENCE_PROJECTS 调研确认全部第三方仓库不可复用资产）。
- 广告模拟实现**不得提审**（RELEASE_CHECKLIST 已列：真实激励视频接入是提审前置条件）。

### 正式/测试隔离（规范要求）

- 浏览器环境：可注入 `platform/mock/MockAdAdapter`（独立目录）用于自动化测试；发奖仅发生在注入模拟适配器的测试路径
- 微信环境：`mode='mock'` 被 AdService 强制判定为 unsupported，**不展示、不发奖**——正式包无法通过测试广告逻辑发奖
- 真实广告：仅在 `mode='wx'` + 合法 adUnitId + 流量主已开通时由 WxPlatform 调用官方 API；未取得广告位前不提交含广告的审核版本
