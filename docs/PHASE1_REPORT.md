# Phase 1 报告 —— 3D 跑酷核心系统

> 日期：2026-11-25。任务书：可实际游玩的第三人称 3D 跑酷原型（角色控制/输入/摄像机/动作系统）。
> 与既有工作关系：三车道/跳跃/滑铲/死亡/相机跟随/程序化动画在 P1（架构阶段）已实现并经 53 项测试；本阶段按任务书补齐缺口并加固。

### 2. 输入系统（input/InputController）

- 滑动三向 + 点按 + 键盘（←→↑↓/WASD/空格）沿用；**ESC/P 暂停切换（PC 调试）**。
- **多点触控**：按 touch ID 跟踪，首个触点持有手势，第二触点不抢占不干扰。
- **输入取消**：TOUCH_CANCEL 丢弃手势（系统打断不误触）。
- **手势阈值配置化**：`input.swipeMin=18 / tapMax=8`；阈值间死区静默丢弃（防误触）。
- 连续操作：触点结束即释放手势归属，连续滑动零间隔；快速连续切道由 targetLane 累计 clamp。
- 鼠标：Cocos 触摸事件天然覆盖鼠标拖拽（编辑器/浏览器预览验证路径）；键盘为 PC 主通道。

### 3. 摄像机系统（render/Renderer3D.updateCamera）

- 位置插值：水平跟随按 `dt*followLerp` 插值（**帧率无关**）；新增**跳跃高度跟随**（`heightFollow=0.18`）。
- **速度相关 fov**：fovBase 58 → +10 随速度公式归一渐变（3/s 插值防跳变）。
- 震屏：事件驱动 + 指数衰减 + **0.25 上限**（防持续抖动）；死亡慢动作黑边/红闪不变。
- 旋转：lookAt 目标随 playerLaneF 缓动（playerLaneF 本身 lerp，无跳变源）。
- **穿模防护**：实体世界 z 越过玩家身后 0.5 即隐藏（BEHIND_HIDE_Z），不再穿过镜头。

### 4. 动画系统（render/CharacterAnimator.ts + ProceduralKuafu.ts）

- **状态接口**：`CharAnimState = idle|run|jump|slide|stumble|dead`，`AnimInput` 由渲染器从核心状态推导（动画层不读核心，可整体替换）。
- **ProceduralKuafu 程序化实现**（几何体驱动，原创零授权风险——优于引入第三方临时模型）：
  run 四肢交替摆动；jump 收腿姿势随进度混合；slide 下蹲前倾；**stumble 高频晃动+手臂乱摆**；**dead 0.5s 前扑倒地插值后保持**；idle 呼吸起伏。
- 后续替换原创绑定模型：实现同一接口即可，渲染器与核心零改动（接口注释已写明）。

### 5. 基础游戏流程

开始（标题点按/Enter）→ 奔跑（**暂停按钮 ❚❚ / ESC/P**）→ **暂停面板（继续奔跑/重新起跑）** → 受击踉跄 → 死亡 → 结算（广告复活/重新起跑）。
HUD 新增：**实时速度显示**（含减速）、暂停按钮/面板、踉跄弹字。
**切后台自动暂停**（`Game.EVENT_HIDE`，微信 onHide 同路径），回前台手动恢复。

## 遗留与说明

1. **"受击"设计决策**：任务书要求受击与死亡并列，实现为"踉跄减速（可承受一次失误）+ 踉跄中再撞/撞墙即死"。这改变了 P0 的即死手感——属任务书驱动的玩法变更，可经 `player.stumble.enabled=false` 完全回退。
2. 帧率一致性中的事件计数（拾取）离散偏差：已量化（9.4% 实测）并定性（RNG 交错翻转），不影响运动一致性（0.01%）；若未来需要跨帧率严格一致的回放系统，须将生成阈值改为距离驱动采样——记入 KNOWN_ISSUES。
3. 真机多点触控/触摸延迟等触感项：待微信开发者工具服务端口开启后人工验证。
